Named for **K8IKO**, whose IC-7410 antenna buttons found a bug that had been sitting in POTACAT's custom CAT commands the whole time. If you have ever typed a raw command into a custom button and watched nothing happen, this release is for you.

## 🧙 Custom CI-V commands now reach the radio

K8IKO set up custom buttons to switch between antenna 1 and antenna 2 on an IC-7410, using the command straight out of the manual — `FE FE 80 E0 12 00 FD`. The button did nothing, and the log said:

```
rx: RPRT -1 (Invalid argument) — likely rejecting "w \xfe\xfe\x80\xe0\x12\x00\xfd"
```

He then sent the exact same bytes with CI-V Scout and the antenna switched. That is what proved the command was right and POTACAT was wrong.

**POTACAT was handing Hamlib the bytes in a format it does not accept.** Hamlib wants each byte written one way and POTACAT wrote it another, so Hamlib rejected the whole command and never sent anything to the radio. Nothing reached the radio to succeed or fail — which is why there was no clue at the rig end.

- **Custom commands with raw hex bytes now work over Hamlib / rigctld.** This affects every radio driven through rigctld, not only Icoms.
- **Both ways of typing them work.** `FE FE 80 E0 12 00 FD` and `FEFE80E01200FD` are the same command. The unspaced form used to be sent as plain text, which is what K8IKO hit when he retyped it without spaces to see if that helped.
- **Direct CI-V serial connections got a fix too.** Spaced hex always worked there, but an unspaced command was misread and put a single meaningless byte on the wire.
- **The custom command box now tells you what it accepts.** Hover it and it names both forms: text commands as your manual prints them, such as `FA014074000;`, and Icom CI-V as hex bytes. It said nothing before, which is why K8IKO reasonably asked whether he had typed it wrong rather than reporting a bug.

Text commands for Yaesu, Kenwood and Elecraft are unchanged. A command that happens to be spelled with letters that are also valid hex, such as Yaesu's `AB`, is still treated as text and not as a byte.
