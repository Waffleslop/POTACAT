Two exceptional bug reports drove this release: a rigctld deep-dive that fixed state tracking for every hamlib/wfview user, and a frozen-app mystery that turned out to be OneDrive. Plus rig name tags and a rig-switching cleanup.

## 📻 rigctld: your radio's knobs finally talk back

A user tested our rigctld support against wfview with real rigor and caught two things at once:

- **Crossed wires (fixed):** with SPLIT and Noise Blanker polled together, their replies could swap — POTACAT's NB indicator followed SPLIT and vice versa. Replies are now matched to queries in the exact order rigctld answers them, with the reporter's reproduction tables as permanent regression tests.
- **Write-only controls (fixed):** most rig state never read back — turn a knob on the radio or in wfview and POTACAT never noticed. Now RF gain, TX power, NR, compressor, VOX, auto-notch, and the preamp/attenuator ladder are all polled and tracked, in POTACAT and on ECHOCAT mobile. Backends that don't support a query get it switched off after one attempt instead of a stream of errors.

## 🖼️ SSTV can no longer freeze the whole app

If your Pictures folder is synced by OneDrive (very common on Windows), opening the SSTV window could freeze all of POTACAT — the received-image gallery was read synchronously, and cloud-only files block until OneDrive delivers them, indefinitely if it's paused or stuck. All gallery reads and writes are now asynchronous: a slow disk or cloud folder costs you a late-loading gallery, never a frozen application.

## 🏷️ Name tags for your rigs

Multi-rig stations: the rig editor gains an optional **Status label** (up to 4 characters — "991", "7300", "FLX"). It replaces the generic "CAT" on the status pills so you can see at a glance which radio is connected, in every state and across rig switches. Blank keeps plain "CAT". Suggested by a user — good idea.

## 🔌 Rig switching: one connection, not a fight

Saving Settings used to start a second connection to your radio in parallel with the one the save itself triggered — with two rigs configured this could spiral into duplicate connections fighting each other and a leftover connection retrying a dead COM port. There is now exactly one reconnect path, rig edits in the rig editor save immediately (closing Settings without the outer Save no longer discards them), and renaming or relabeling a rig never touches the connection.
