# Settings reference (developer)

Every key in settings.json as documented in the old CLAUDE.md, moved here verbatim on 2026-11-09. The user-facing list is in the Users Guide (userguide/src/settings-reference.md). Some early entries are out of date: `catTarget` now lives per rig under `rigs[]`, and `watchlist` accepts state codes. Correct an entry when you touch the code behind it. JTCAT keys are summarised in docs/JTCAT.md.

- `grid` — Maidenhead grid square (default: FN20jb)
- `catTarget` — `{type, host, port}` or `{type, path}` for serial
- `distUnit` — 'mi' or 'km'
- `scanDwell` — seconds per frequency during scan (default: 7)
- `cwXit` — CW XIT offset in Hz, range -999 to +999 (default: 0)
- `watchlist` — comma-separated callsign string
- `enablePota` — show POTA spots (default: true)
- `enableSota` — show SOTA spots (default: false)
- `enableWwbota` — show WWBOTA (bunker) spots (default: true)
- `enableGma` — show GMA (Global Mountain Activity) spots (default: false, opt-in); `panadapterGma` for the panadapter-only gate
- `enableParc` — show PARC (Protected Area Radio Community) spots (default: false, opt-in); `panadapterParc` for the panadapter-only gate
- `wwbotaRespotTemplate` — comment template used when re-spotting WWBOTA after a QSO (blank = fall back to `respotTemplate`)
- `enableCluster` — enable DX Cluster telnet (default: false)
- `enableRbn` — enable Reverse Beacon Network view (default: false)
- `myCallsign` — callsign for DX cluster and RBN login
- `clusterHost` — cluster node hostname (default: w3lpl.net)
- `clusterPort` — cluster node port (default: 7373)
- `enableDxcc` — show DXCC Tracker view (default: false)
- `adifPath` — path to ADIF file for DXCC tracker
- `tciSpots` — push spots to TCI panadapter (default: false)
- `tciHost` — TCI server hostname (default: 127.0.0.1)
- `tciPort` — TCI server port (default: 50001)
- `tciPota/tciSota/tciCluster/tciRbn/tciWwff/tciLlota/tciPskr` — per-source filters for TCI spots
- `tciMaxAge` — max spot age in minutes for TCI (0 = no limit, default: 15)
- `ultracat` — ULTRACAT mode unlock (machine-scoped GLOBAL_KEY, default false). Hidden tier-2 easter egg: CTRL+SHIFT+click the π in Settings (The Net). Reveals the JTCAT popout's Full Auto CQ controls. Revoke with CTRL+ALT+SHIFT+click.
- `echoTxGuardMs` — ECHOCAT first-syllable PTT guard: fixed DelayNode (ms) on the phone-mic→rig path in remote-audio.html so speech at the instant of key-down isn't clipped (default 120, 0=off, clamp 300; DAX-direct path only — the setSinkId path has no WebAudio graph). Part of the audio-prewarm work: the bridge window pre-warms at client connect WITHOUT capture (no JTCAT/SSTV device contention; `prewarmRemoteAudioWindow` + pending-start flag in main.js), TURN creds pre-mint at connect, `[audio] offer sent Nms` log + `ptt-applied {ms}` WS reply instrument the latencies.
- `enableMercury` (default off) + `mercuryPath` (binary override) / `mercuryBasePort` (8300; control=base, data=base+1) / `mercuryBroadcastPort` (8100, KISS/Reticulum, later) / `mercurySoundSystem` / `mercuryInputDevice` / `mercuryOutputDevice` / `mercuryCaptureChannel` / `mercuryTxGainDb` (±20 dB → Mercury `[audio] tx_gain_db`) / `mercuryVerbose` — Mercury HF data modem launch config (see lib/mercury-process.js). Relaunched only when a launch-relevant key changes (`mercuryChanged` in save-settings — the rigctld respawn-race lesson); killed in `gracefulCleanup`. ini regenerated per launch into userData. **Settings UI: Settings ▸ Station ▸ "Mercury (HF data)"** (enable + binary path/Browse + sound system + in/out device + BW + TX gain + Listen; modeled on the TCI block, renderer/app.js refs+toggle+load+persist; the More▾ "Mercury HF Data" menu item [view-mercury-btn] reveals live on save). Includes install instructions with a clickable download link (needs the Rhizomatica domains in the open-external allowlist in main.js). **Device-discovery wizard** ("Discover devices" button): `mercury-list-devices` IPC runs `mercury -x <ss> -z` → `parseSoundcardList` (lib/mercury-process.js, pure/tested) → clickable capture/playback pickers that fill In/Out with the device id; auto-matches the active rig's DAX by resolving rig.remoteAudioInput/Output ids → mediaDevice labels → token-match vs Mercury names. Status via `[Mercury]` CAT-log lines + `mercury-status` IPC.
- `mercuryAudioBridge` (`auto`|`device`|`fifo`, default `auto`) — how Mercury reaches the radio (Phase 4, lib/mercury-audio-bridge.js `resolveMercuryAudio`). `device`=Mercury opens a real sound device (`-x wasapi/alsa/coreaudio` + mercuryInputDevice/OutputDevice). `fifo`=POTACAT bridges Mercury's s32le@8kHz FIFOs into its own SmartSDR/Icom routes (no virtual audio device) — **LINUX/MAC ONLY**: Mercury's fifo backend is POSIX `open()`+O_NONBLOCK under `#ifndef FF_WIN` (spike 2026-07-14), so Windows named pipes can't drive it and `fifo` silently resolves to `device` on win32. `auto`=fifo for Flex/Icom-network on a fifo-capable OS, else device. **Phase 4a shipped** (pure core: `s32leToF32`/`f32ToS32LE`/`StreamingResampler` continuity-preserving 8k↔12k + resolver, all tested; `buildMercuryArgs`/`Ini` take a resolved `audio`; `resolveMercuryAudioStrategy` in main.js logs the choice). **Phase 4b deferred** (the POSIX FIFO transport + the main.js RX-tap→rxFifo / txFifo→3-route-TX-dispatch pumping — needs Linux+Mercury+rig): a resolved `fifo` is currently logged and coerced to `device`.
- `mercuryListen` (default OFF) — put Mercury in LISTEN so it answers inbound ARQ calls. Default off because an inbound CALL keys PTT and Part 97 wants that attended. When on, `onMercuryReady` acquires the radio-owner lock ('mercury') up-front (an inbound call will key), so JTCAT is blocked while Mercury listens. `mercuryBw` (500|2300|2750) — ARQ bandwidth ceiling sent on connect. Phase 3: Mercury's control-socket `PTT ON/OFF` drives `handleRemotePtt(state,{audio:true})` + a rolling 30s TX failsafe (`armMercuryTxFailsafe`); ARQ session claims the radio via the pure `lib/radio-owner.js` arbiter (`none|jtcat|mercury` mutex — `acquireRadio`/`releaseRadio`/`radioOwner`); JTCAT's `tx-start` is blocked (and `tx-end` won't drop Mercury's PTT) while Mercury owns; on collision Mercury `abort()`s to yield. JTCAT acquires 'jtcat' for each transmission (tx-start→tx-end). SSTV/WSPR/tune tx-start guards = follow-up.
- `wsprPreCapPower` — `{watts, rigId, at}`, GLOBAL_KEY, written by the WSPR beacon: the RF power it found on the radio before `wsprForcePowerCap()` set 1 W. The cap used to be one-way by design ("raise it in your radio for other modes"), and on a Flex rfpower PERSISTS IN THE RADIO across restarts, Flex Direct shows no SmartSDR slider, the SmartSDR Direct dax_tx route applies no audio gain (so the popout's old "TX Pwr" audio slider was a no-op), and until d07752f the wattmeter showed 30 dBm as "30 W" — K3SBP's 8600M sat at 1 W for ~4 weeks of unanswered FT8 CQs (2026-09-10). Policy is the pure `lib/wspr-power-memory.js` (`rememberPreCapPower`/`decideRestore`/`decideReconcile`, test/wspr-power-memory-test.js with source-text guards on main.js); main.js executes it in `wsprRememberPreCapPower` (at arm, BEFORE the cap), `wsprRestorePreCapPower` (disarm, mode switch, `stopJtcat`, and `gracefulCleanup` — placed BEFORE cat/SmartSDR disconnect; deferred with a 1 s retry while a WSPR frame is mid-air; 3 attempts then give up) and `wsprReconcilePreCapPower` (hooked in `sendCatPower`). **The marker is cleared ONLY by a power readback above the cap, never by a command having been sent** — so a crash, kill, or quit that closed the socket before the write flushed is repaired by the next session's first `sub tx all` readback (readback ≤ cap + marker + beacon not armed → restore). An explicit operator `set-tx-power` (desktop dispatcher or ECHOCAT `set-txpower`) forgets the marker when the beacon is not armed, so a restore never fights deliberate QRP. Log tells: `[JTCAT] TX start: <mode> "<msg>" @ N Hz, RF power set to N W` on every JTCAT key-down, `[JTCAT] WARNING: transmitting <mode> with the radio's RF power at 1 W — the WSPR beacon cap` (+ one toast per level to popout and main window), and `; RF power set to N W` on the Flex `[TX] RF out:` line. **JTCAT popout audio bar:** `TX Pwr` is now the RADIO's RF power in watts (`jtcat-rig-power` push from `broadcastRigState`, deduped by content; range/select from model caps; written through `rig-control set-tx-power`; the value turns red at ≤1 W in a non-WSPR mode), `Drive` is the old `jtcatTxGain` audio slider (dimmed with a tooltip on the SmartSDR Direct route), `PWR` is measured forward power (`cat-fwd-power` forwarded to the popout).
- `swrGuard` (default on) + `swrGuardMax` (1.5–10, default 3.0) — Flex-only SWR guard: the Flex folds back power into a bad match but never refuses to key, so POTACAT watches the radio's TX bridge (`swr-ratio`, raw/128 true ratio) and aborts any transmission whose SWR stays over the limit for 3 consecutive frames, then LATCHES (all TX paths refuse: jtcat tx-start, startJtcatTune, handleRemotePtt). **A Flex tune does NOT clear the latch — only the radio's reported MATCH does** (K3SBP 2026-09-13, 19:1 on 20 m): `setAtu` is wrapped at construction to open a result-awaiting episode (`noteAtuTuneStarted({awaitResult:true})`, suppresses tripping during the sweep), `lib/smartsdr.js _parseAtuStatus` emits the `atu status=` stream (`sub atu all`), and `onAtuStatus` resolves it via the pure `lib/swr-guard.js decideAtuOutcome` — TUNE_OK/TUNE_SUCCESSFUL → `clearSwrTrip`, TUNE_FAIL_BYPASS/ABORTED/idle-after-sweep → stays latched with an "ATU could not match … check the antenna" message on every surface, silence for 20 s → stays latched. Until then the latch cleared when `atu start` was SENT, so `swrAutoTune` (JS8 ⚙ toggle) turned a fault into tune → re-key at full power → trip, blind for 30 s between, and the log never said the tune had failed. `decideSwrAutoTune` also refuses the auto-tune above 10:1 (no ATU matches that — the tune is 10 W into the fault), once per band per session after a reported failure (a later successful tune on that band forgets it), and more than once a minute. The non-Flex tune paths (CAT `startTune`, rf-sense external tuner) report nothing back, so there `noteAtuTuneStarted()` still clears the latch outright. Latch also clears on band change (checked in sendCatFrequency, the single freq sink — which also drops a pending episode) or `swr-guard-override` IPC. Tests: `test/swr-guard-test.js` (policy + source-text guards on main.js). Settings UI lives in the rig editor's Flex section (rig-scoped). SWR is only measurable DURING TX — deliberately no stale pre-TX prediction.
- `launchAtStartup` — start POTACAT at OS login (default false, GLOBAL_KEY). Settings > Station. Applied live on save + re-asserted at app boot when true (`applyLaunchAtStartup` in main.js): Win/mac via `app.setLoginItemSettings` (packaged only — dev would register electron.exe), Linux via XDG `~/.config/autostart/potacat.desktop` (APPIMAGE path when set). Never writes the OS state when false at boot.
- `pskAudioCenter` — PSK31 audio center Hz (default 1500, persisted on Send); `pskMacros` — `[{label,text}]`, SIX slots canonical (W4MPT 2026-07-12): defaults CQ / Call (answer a CQ) / Exch (report) / Brag / 73 / blank free-text. User-editable in the popout: right-click a macro button (or left-click a blank slot) opens the inline editor, Save persists all six, "Reset all" saves `pskMacros: null` (spread-merge overwrite → defaults on next build). `pskNormalizeMacros` pads a short saved array with blank `M#` slots, NOT defaults (a legacy 4-macro custom set must not sprout a duplicate default 73). $MYCALL/$GRID/$CALL substitution; $CALL = the "their call" box, filled by double-clicking a callsign in the RX text
- `txDrive` — SHACK-side TX drive percent 0–200 (100 = unity, default 100), per-rig (`rig.txDrive`) with `settings.txDrive` as the global mirror (same pattern as `remoteAudioOutput`; rides `switch-rig`). The level of the CLIENT-MIC audio POTACAT feeds the radio — NOT a client-local mic gain (the web client's own `#rc-tx-gain` scales that browser's mic pre-WebRTC and never leaves the page; reserve the name "mic level" for any future client-local gain). ONE choke point: `ipcMain.on('tx-drive-set')` in main.js — clamp, persist global+rig, push `tx-drive-update` to the bridge/main/VFO windows, echo S2C `tx-drive-state`. Wire: C2S `set-tx-drive {value}` (Guest Pass REFUSED in the remote-server demux, which re-echoes the true value so a guest's slider snaps back), S2C `tx-drive-state {value}` hydrated at connect, hello capability `tx-drive`. Bridge (renderer/remote-audio.html): a GainNode ahead of the EQ chain on the DAX-direct path (full 0–200); the setSinkId route has no WebAudio graph so it drives `<audio>.volume` and CLAMPS above 100% with a status note. Paired readout = the existing S2C `tx-meter` push (now registered in the protocol so mobile can mirror it).
- **Text size** (Settings > Display, 2026-10-16) — NOT a settings.json key: the window zoom factor in localStorage `pota-cat-zoom` (60–200%, 10% steps). `setUiZoom()` in renderer/app.js is the ONE writer, shared by the row's −/+/Reset, the Ctrl +/−/0 keys and the startup restore, so the readout always matches the keys. Searchable under "font". Pop-outs keep their own zoom (conditions pop-out = `settings.conditionsPopoutZoom`).
- `jtcatWaterfallSpeed` — JTCAT popout waterfall lines/sec (1–60, default 60 = legacy one-line-per-animation-frame), GLOBAL_KEY, edited in the popout's gear popover under "Display". The canvas is only **80 px tall**, so 60 lines/sec holds ~1.3 s of history and a 15 s FT8 transmission paints ~900 lines — the "endless worms" look. Lower values give WSJT-X-like per-transmission blocks with whole periods on screen (5 ≈ one period, 2 ≈ three). Frames between drawn lines are **averaged, not dropped** (WSJT-X N-average equivalent), so slowing down integrates weak signals instead of losing them. `>= 60` short-circuits to draw-every-frame so the default is bit-identical to the old behavior. Casey 2026-08-04.
- `jtcatWaterfallFloor` — JTCAT popout waterfall display noise floor 0–200 (default 0), GLOBAL_KEY, slider under ⚙ > Display next to speed. `ScopeAxis.applyFloor` — the same control the Band Scope has — applied AFTER the RX-silent watchdog reads the raw bins (a high floor must never fake "RX audio silent") and to the per-slice mini waterfalls. Display only; decoding is untouched. (Casey 2026-09-21, after the first FT-710 owner asked for it on the scope.)
- `jtcatShowBandScope` — JTCAT popout shows the FT-710 band scope as a strip above the audio waterfall (default off; ⚙ > Display toggle, shown only when `scope-state.available`), GLOBAL_KEY. main fans `scope-frame`/`scope-state` to the JTCAT window while it watches (`jtcat-scope-watch` IPC — the window counts as a watcher in `yaesuScopeWanted()`, exactly like a subscribed ECHOCAT client); the strip shares the JTCAT floor slider. ECHOCAT Web has the same strip in the FT8 tab behind a BS button (`ft8BsOn`, localStorage), drawn by the same N-surface scope code as its Scope tab. (Casey 2026-09-21)
- `jtcatRxGain` — JTCAT RX gain 0–1 (default 1), GLOBAL_KEY. The ONE synced value behind the RX sliders on all three surfaces (main-window JTCAT view, popout, ECHOCAT clients) — they were three unsynced localStorage copies until 2026-07-20; the popout's copy at 0 caused the 2026-07-18 blank-waterfall night. `applyJtcatRxGain(value, origin)` in main.js is the only writer: clamps, persists (debounced), relays `jtcat-set-rx-gain` to the non-origin windows, echoes S2C `jtcat-rx-gain-state` to remote clients (skipping origin 'remote' so a dragging phone isn't fought). C2S `jtcat-rx-gain {value}` sets it; state hydrates at connect; hello capability `rx-gain-sync` gates the mobile slider. Popouts migrate their old localStorage value into the setting on first run. **Per-band memory (`jtcatRxGainByBand`, GLOBAL_KEY, 2026-08-05):** the level that hears 17m isn't the level that hears 20m, so every operator change is filed under the current band and a band change restores that band's level. `jtcatRxGain` remains the LIVE/last value (what every surface hydrates from at connect, and the fallback for a band never set). Restore is driven by `jtcatRxGainFollowBand()` from `sendCatFrequency` — the single sink every frequency source funnels through (tune, knob, scan, spot click, WSPR hop, remote), same hook point as the SWR-guard band-change clear, so no per-path wiring. A band with nothing stored KEEPS the current level (it becomes that band's on the first adjustment) rather than snapping to a default. The restore calls `applyJtcatRxGain(v, 'band')` and that origin is the one that does NOT write back to the map.
- `jtcatTxGain` — JTCAT TX power 0–1 (the GAIN, `(pct/100)^2` square-curve domain the sliders already exchange; default = 100% = 1.0), GLOBAL_KEY. **Desktop-authoritative since 2026-09-09 (NA7C), cloned from `jtcatRxGain`:** `applyJtcatTxGain(value, origin)` in main.js is the only writer — clamps, persists (debounced), drives `_jtcatDirectTxGainLevel` (Icom-network/tune routes), relays `jtcat-set-tx-gain` to the non-origin windows, echoes S2C `jtcat-tx-gain-state` to remote clients, and LOGS the settled value with its origin (`[JTCAT] TX power set to N% by the ECHOCAT client`, plus a WARNING at ≤5%). The tx-start renderer payload carries `txGain` so the level that goes out is the one the log records, and the renderer's `[JTCAT TX] starting buffer source` line now says `txPwr=N%`. C2S `jtcat-tx-gain {value}` sets it; state hydrates at connect; hello capability `tx-gain-sync`. **Why:** TX had stayed three unsynced localStorage copies after RX was fixed — the ECHOCAT web client re-pushed ITS saved copy on every connect, the popout slider never heard anyone else's moves, and no log line recorded the level. One phone set to 5% therefore keyed the shack's IC-7300 with no audio for three weeks (red TX LED, 0 W, no SWR) while the desktop slider read 100% and WSJT-X worked first try. Clients must never push a saved local copy at connect. The native app declares `jtcat-tx-gain` with field `level` (desktop reads `value`) but has never sent it; a mobile slider should hydrate from `jtcat-tx-gain-state`.
- `jtcatMaxQsoAttempts` — per-phase TX cap (1–60, default 12): max transmissions of the same message per QSO phase, heard or not (the old heard-reset let a partner repeating a non-advancing message hang the QSO forever; KQ4MHD 2026-07-10). A try = a TRANSMISSION, gated by `shouldCountRetry` (lib/jtcat-state-machine.js) on the tx-start-stamped `_lastTxPeriodKey` — until 2026-08-04 every non-advancing DECODE PERIOD counted (own-TX periods included), burning the cap 2× per QSO cycle ("tries 5 gave up after 3", KQ4MHD). On cap: reports exchanged both ways (reply-side r+report) → graceful closeout (log + one final courtesy 73 via `canCloseoutQso`/`closeoutStalledQso`); run mode → resume CQ; else halt TX unlogged (`giveUpMessage` flavors). Policy = `decideRetryOutcome` in lib/jtcat-state-machine.js, executed by ONE `jtcatHandleRetryStall` in main.js shared by all four decode paths (popout/remote × single/multi-slice; also dedupes per FT8 period so N slices don't burn N tries/cycle). The popout `tries` input is public UI (un-gated from ULTRACAT 2026-07-10).
- `jtcatReworkDays` — worked-before expiry for JTCAT's automatic paths (0 = never expires, the default; N = same-band/mode log entries older than N days stop blocking Hunt/Run). Per-profile operating policy like `jtcatMaxQsoAttempts`, edited in the popout gear popover. Policy is the pure `decideWorkedBefore()` in `lib/worked-before.js` (test/worked-before-test.js), which ALSO carries the program-activator exception: a station currently spotted at a park (via `HuntedPark.findHuntedRefs`) only blocks if already worked on this band+mode at one of TODAY's spotted parks on today's UTC day — new park or new day counts fresh, matching POTA credit rules. `jtcatWorkableCallers`' default isWorked was a bare any-band-ever `workedQsos.has()` and Hunt's answer path used it — now defaults to the one `jtcatIsWorkedCall` definition. Manual double-click replies still always transmit; the toast tail explains a non-blocking dupe. (KQ4MHD 2026-08-17)
- `jtcatHuntSpotted` — POTA/SOTA Hunt also answers a **plain CQ** from a station the live spot list places at a park/summit (default **true**, per-profile, popout gear popover). Hunt used to require the decode to literally start `CQ POTA ` / `CQ SOTA `, and most activators never send the modifier — it costs characters in a 13-character message and buys them nothing, since their hunters came from the spot page. POTA hunt could therefore sit silent through an entire activation it was hearing perfectly. The cross-reference is the SAME `HuntedPark.findHuntedRefs` lookup that stamps the park onto the logged QSO (90-min spot window, same-band ranked first), so a station hunted this way logs with its reference automatically. Policy is the pure `matchesHuntFilter()` in `lib/jtcat-state-machine.js` (test/jtcat-test.js); main supplies `spottedSigs` from the merged spot list. **Still requires a CQ** — answering a decode addressed to someone else is how you QRM the activation you came to work; tail-ending an activator's RR73 is a separate, deliberate behaviour change. Field Day hunt is never spot-matched. (2026-09-02)
- `jtcatNferParks` — a hunted JTCAT contact is logged at **every park of an n-fer** the activator's own spot names (default **true**, Casey 2026-11-12; per-profile, Options; #353 by DA2PK). A POTA spot carries one reference; an activator in several parks self-spots one and lists the rest in the comment. The rule is the header of `lib/nfer-refs.js`; every part of it is an ALLOW-list because a park read from free text reaches the log, the Cloud journal and the external logbook. WHEN: only with pota.app's history for call + park (`/spot/comments/{call}/{ref}`, 10 s timeout, 512 kB cap) fetched successfully in the last 3 minutes (`NferCache.fresh`; ttl 2 min; a failed request empties the entry); `_potaSpotHistory` is passed as `buffer` and can only take parks away. WHICH SPOT: the newest of the activator's own spots (`JtcatParser.baseCall`) in the last 90 minutes decides alone; posted at another park = they moved, nothing; an own spot at the park with an unreadable time = nothing. WHAT COMMENT: one list of parks, (a) with an n-fer word carrying a number and exactly that many parks, or (b) joined by `,` `+` `&` `/` `;` `and`, at most three extras, each confirmed by the parks catalogue; and EVERY other token neutral (mode, one band label, a frequency inside a ham band, a 6-character grid, QRV, CQ, POTA, kHz/MHz; 73/TNX/THX/TU behind the list; punctuation; one `[app tag]`, a trailing `Self-spotted via <app>`). Any other word anywhere, a WWFF or foreign reference, or a comment over 500 characters: nothing. Same prefix as the spotted park (`K-` read as `US-`). The history is fetched while a QSO with a spotted POTA activator is under way (`jtcatNferPrefetch`, from the two QSO-state broadcasts, which a slice's QSO passes too), never per decode, and read without waiting at log time (`jtcatNferExtras`, wrapped so a throw logs the spot-list park). The extras are only pushed into `qsoData.hunted`; `hunted.refs` stays the spot list's, so a re-spot never uses a park read from a comment. The QSO logged card says "at US-1111 and US-2222" and names the parks that came from the comment; the same text goes as S2C `jtcat-qso-logged` to clients that declared that capability (ECHOCAT Web toasts it when parks came from a comment), and the Log QSO review bar shows the note until the reference box is edited. A device reads the setting in the settings frame and sets it with `jtcat-set-pref`. Tests: `test/nfer-refs-test.js`, real comments in `test/fixtures/nfer-real-comments.json`.
- `jtcatModeHop` / `jtcatModeHopModes` / `jtcatModeHopIdleMin` — **FTx mode hopping** (default OFF; modes `['FT8','FT4','FT2']`; idle 3 min, 1–60). "Automatic band hopping ... specifically for FT4 & FT2 ... there seems to be so little use on those modes" — Barry 2026-09-07. It hops the **MODE and never the band**: a band change means retuning the antenna, and starting an ATU sweep from a background timer is not a thing to do behind the operator's back, whereas FT8/FT4/FT2 each have a watering hole *inside* the same band (20m: 14074 / 14080 / 14084), so the carousel is a few kHz of VFO with the antenna, tuner and amp untouched. Public (not ULTRACAT-gated), per-profile, edited in the popout ⚙ popover. **Only fires while Hunt or Auto CQ is running** — someone just watching the waterfall must never find the VFO moving on its own. Policy is the pure `decideModeHop()` in `lib/jtcat-modehop.js` (test/jtcat-test.js "Mode hop" section); execution is `jtcatModeHopTick`/`jtcatHopMode` in main.js. Load-bearing pieces: (1) **idle = no WORKABLE callers**, the same `jtcatWorkableCallers` definition Hunt and Run run on — counting raw decodes would pin you to FT8 forever precisely because FT8 is always busy, and since worked-before is band AND mode aware the stations that just drained FT8 are *fresh contacts* one watering hole over, which is the whole return on the feature; (2) the threshold is in **minutes, converted per-mode** (`periodsForMinutes`) because 12 periods is 3 minutes of FT8 but 45 seconds of FT2; (3) the counter is **period-gated** (`_jtcatModeHopPeriod`) or N slices reach the threshold N× too fast — the Hunt-fallback quiet-counter lesson; (4) `jtcatModeHopAvailable()` filters to modes with a dial **on the current band** (6m has no FT2, 2m has neither FT4 nor FT2) so the pure decision never needs a frequency table; (5) `_jtcatExpectedDialHz` is re-anchored on every hop or the wrong-band TX guard blocks the first transmission on the new mode and blames a spot click; (6) refused mid-QSO, while keyed, while a **spot target** is armed (the operator picked that call on *this* mode), and in multi-slice (N bands already, no single mode to hop); (7) any band change under us (spot click, scanner, knob, phone) resets the clock, detected by comparing the band each tick rather than hooking every QSY path. **Precedence over the ULTRACAT Hunt→Run fallback** (`jtcatModeHopDefersCqFallback`): that fallback's threshold is ~1 min of FT8 and would otherwise fire first every time, so the carousel goes first — hopping to where someone may already be calling beats manufacturing activity — until a full lap produces nobody. Run's drained band hops instead of pausing (`jtcatHopModeForDrainedRun`, which zeroes `jtcatFullAutoCqUnanswered` or the next CQ would trip the drained test again and sprint through the whole carousel); a completed lap **while running** stops the carousel so the pause can happen, while a lap while only *hunting* keeps circling because listening costs nothing. Announced on `jtcat-mode-hopped` (IPC + S2C) so the popout's mode select, band dials and decode panes follow; the **mobile client's JTCAT tab does not consume it yet** (handoff).
- `jtcatLogPrompt` — review a JTCAT contact in the Log QSO window before it is written (AE5JE 2026-11-02, WSJT-X's prompt; default off, per-profile, Options). `lib/log-review.js`: **main holds the whole record** (the form has no box for a heard grid, a Field Day exchange or a second program's park) and `mergeEdits` lays the form's edits over it, so what the form cannot show survives; contacts QUEUE; a half-typed form is never wiped (`offerReview` holds the contact until the form is empty). Only QSOs run from the JTCAT window (`jtcatAutoLog(q, {fromWindow:true})`): a phone-run QSO always logs by itself, and the setting is deliberately NOT in JTCAT_PREFS. The re-log guard is marked at enqueue and `holds()` makes `jtcatIsWorkedCall` true, or Run re-works the station while the form waits; Don't log / the X clears both. Run and Hunt: the form opens without focus (`_logPopoutQuiet`). Quitting writes what waits (`before-quit` preventDefault, `jtcatFlushLogReviews`); `_appWindowsClosing` stops the main window's close of every pop-out reading as a decline. A crash loses what is waiting. `jtcatWriteLog` is the one write, and a failed log now says so on screen (it was console.error only). Tests: test/log-review-test.js.
- `jtcatRelogCooldownMin` — JTCAT re-log guard (default 15, 0 = off, 0–120, per-profile, gear menu). Answering a repeated R-report after RR73 starts a NEW QSO object, so the per-QSO `_logged` flag cannot see it and the same contact was logged and forwarded twice (K9CYT 2026-10-04). `jtcatAutoLog` skips a call already auto-logged on the same band+mode inside the window (`lib/jtcat-relog-guard.js`, pure); the RR73 still goes out, an orange `jtcat-dupe-warning` toast + `[JTCAT] Not logged again:` log line say why. Only a SAVED log is remembered. Tests: `test/k9cyt-requests-test.js`.
- `sstvSaveAllDecodes` — SSTV "Save every picture, even partial ones" (default off, SSTV gear menu). Weak-tier decodes (shown, normally not saved) are kept in the gallery with `partial` in the filename and `partial: true` in the sidecar; gate-rejected noise is never emitted so never saved. Applies to the single-receiver AND multi-band paths (the multi-band path used to save weak decodes unconditionally). JS8 free text with no address is sent identified, `MYCALL: text` (`js8-engine.js` passes `forceIdentify: true`, JS8Call's default); the pop-out's To list has "No address" and the chips are JS8Call's directed commands (K9CYT 2026-10-04).
- `jtcatRunPauseAfter` — unanswered CQs before ULTRACAT Run stops transmitting and just listens (0–60, default 8 ≈ 4 min of FT8; **0 = never pause**, the pre-2026-08-05 behavior). Per-profile (NOT a GLOBAL_KEY — it's operating policy, like its neighbour `jtcatMaxQsoAttempts`, not a machine/display property). Edited in the JTCAT popout's ⚙ popover, ULTRACAT-gated. See the ULTRACAT section for the full pause/resume design.
- `jtcatApDecode` — a priori (AP) FT8 decode, default **true**. The RX mirror of late-start TX: the native decoder runs extra LDPC passes that hypothesize known bits to recover marginal/late replies addressed to us. Two passes, tried only after the plain decode fails a candidate: **AP1 "mycall"** (call1 = our call, i3=1 — any reply to our CQ) and **AP2 "both"** (call1 = our call, call2 = the station we're working — mid-QSO, up to ~10 dB on bad channels). Native plumbing: `ftx_decode_candidate_ap()` in `decode.c` clamps the masked bit LLRs to ±40 after normalization (positive LLR → 1 per `bp_decode`); `ft8_addon.c` builds the masks once from a probe std message (via `ftx_message_encode_std` + a throwaway hash interface) over fixed bit ranges (call1+ipa 0–28, call2+ipb 29–57, i3 74–76), tries AP2 then AP1, guards against false-accepts by requiring the unpacked text to contain our call, and tags results `ap:true`. The CRC gate is unchanged — AP biases, never bypasses. `myCall` is authoritative from settings (`setApContext`); `dxCall` is auto-derived from the engine's TX message (first token of a directed reply). UI: "AP RX" checkbox. Empirically validated (`scripts/test-ap-decode.js`): rescues 5 s-late replies the plain decoder misses, zero false positives on others' QSOs. **This is the Phase 2 that the late-start handoff scoped.**
- `jtcatLateStartTx` — late-start TX (WSJT-X waveform-truncation parity), default **true**, FT8-only. A user-tap reply that lands 0.5–7 s into the slot still transmits instead of deferring: the engine attaches a `lateStart` plan, and `main.js` slices the leading symbols off the pre-rendered buffer ONCE at the `tx-start` dispatch choke point (so all audio routes — SmartSDR direct, Icom network, renderer DAX, failsafe — get the truncated buffer) and rewrites `offsetMs` to a small PTT-settle lead. The buffer **tail is preserved**, so PTT-off stays at slot+13.14 s (no bleed into the responder's next slot — the distinction from the reverted pad-and-play-full-late path). The leading Costas is sacrificed; the receiver re-syncs on the middle/end Costas arrays. Slice/ramp/plan math is the pure, unit-tested `Ft8Engine.computeLateStartPlan()` + `sliceLateStartBuffer()` (`lib/ft8-engine-test.js`). UI: "Late TX" checkbox by "Hold TX". Phase 2 (receive-side AP-mycall decode) is a separate, deferred spike.
- `jtcatSkipTx1` — Skip Grid reply (WSJT-X "disable Tx1"), default OFF. Popout "Skip Grid" toggle. Answering a CQ sends `THEIRCALL MYCALL -NN` (signal report) instead of the grid, cutting one full cycle each way; the QSO's `sentReport` is pre-set so the state machine's reply-phase R-branch preserves what we actually transmitted. Receive side (compressed replies TO our CQ) predates this and is separate. Ignored in FD and Hound modes. (2026-07-07)
- `jtcatHoundMode` — FT8 DXpedition Hound (old-style Fox/Hound), default OFF. Popout "Hound" toggle. Rules implemented: initial call forced ≥1000 Hz (fox zone is 300–900), hounds call the fox's BASE call (grid kept in Tx1), fox dual messages (`K1ABC RR73; W9XYZ <KH1/KH7Z> -08`, type 0.1 — codec added to message.c) parsed segment-wise so another hound's payload can't advance our QSO, TX auto-QSYs to the fox's frequency for the R+rpt leg, RR73 logs + kills TX with NO 73 courtesy. `q.hound` set by both reply handlers. **SuperFox is NOT supported** (needs the sfox waveform decoder, absent from ft8_lib) — old-style F/H only. Needs on-air validation against a real fox. (2026-07-07)
- **Nonstandard/special-event callsigns (GB13COL, PJ4/K1ABC)** — fully workable as of 2026-07-07. Native: `pack28` accepts bracketed `<CALL>` (hash-22), `encode_std` rejects double-hash/hashed-CQ so RRR/RR73/73 legs fall through to type 4 (full call out), `encode_nonstd` bracket-strip + `len_call_de` bug fix, addon encode uses the live hash_if (was NULL → every bracketed message silently failed to TX). JS: `JtcatParser.isStandardCall()` mirrors `pack_basecall` (1x1/2x1 calls like W1A/K2A ARE standard; slash/displaced-digit are not), `formatDirectedMsg()` owns the bracket rules (report legs hash the nonstd call, ack legs send it full, grids dropped, both-nonstd refused) and is used by ALL TX builders (state machine `_directedMsg`, main.js `jtcatDirectedMsg` ×17 sites); state-machine matching strips `<>` (`_normText`), bare two-call replies (nonstd caller, no grid possible) advance the CQ ladder; AP2 gated off for nonstd DX calls (masks assume std c28 bit ranges). Round-trip suite: `scripts/test-nonstd-roundtrip.js` (19 cases incl. cold-listener `<...>`). Caveat: bracketed/nonstd TX is native-encoder-only — the ft8js WASM fallback can't pack it. (Until 2026-08-03 the worker routed FT4 TX *only* to the JS ft4 encoder, so an FT4 reply to a slash call silently never keyed while the QSO loop kept "calling" — KF0U/W1AW/4. ft8-worker now prefers native encode for FT4 too, and encode refusals surface as `[JTCAT] TX ENCODE FAILED` in the CAT log via the engine's `encode-failed` event.)
- **Manual TX message** — click the TX message in the popout to type any message; Enter validates via `jtcat-validate-tx-msg` (runs the REAL native encode, so accepts ⇔ transmittable), red border + reason on reject, Esc/blur cancels. Does NOT arm TX (Enable TX stays deliberate). Display writes go through `setTxMsgDisplay()` so broadcasts don't clobber an open editor. (2026-07-07)

- `jtcatFdMode` / `jtcatFdExch` — ARRL Field Day mode (default OFF). When on, JTCAT calls `CQ FD` and runs the Field Day QSO sequence: a **class + ARRL/RAC section** exchange replaces grid AND the dB signal-report step (one message shorter each way). `jtcatFdExch` is the operator's own exchange, e.g. `"2A EMA"` (transmitters+class, then section). The FT8 message type is i3=0 n3=3/4 (`WA9XYZ KA1ABC R 16A EMA`), implemented **bit-exact to WSJT-X packjt77.f90** in the native codec: `ftx_message_encode_arrl_fd()` / `ftx_message_decode_arrl_fd()` + the 84-entry `arrl_fd_sections[]` table in `lib/ft8_native/ft8_lib/ft8/message.c`; the addon gained a native `encode` export (`ft8_addon.c`, GFSK synth) because the ft8js WASM encoder can't pack FD — the worker prefers native encode, falls back to ft8js. UI: "FD" toggle + exchange field in the JTCAT popout. Wired into the popout CQ/Auto-CQ + double-click-answer paths; remote/phone/multi-slice/mid-QSO-click are follow-ups. **Requires the native addon rebuilt** (`npm run build-ft8`). FT8 only for now (FT4/FT2 deferred). Round-trip tests: native standalone + `test/jtcat-test.js` FD section.

## ULTRACAT — Full Auto CQ (hidden)
Unlocked via the π easter egg (`settings.ultracat`). Adds one ULTRACAT-gated control to the JTCAT popout: an **Auto CQ** toggle (run mode — call CQ, work answerers, re-arm CQ forever). (The **tries** input (`jtcatMaxQsoAttempts`) was ULTRACAT-gated too until 2026-07-10; it's public UI now — see the setting's entry above.) Run mode lives in main.js (`startFullAutoCq`/`rearmCq`/`stopFullAutoCq`), is **popout-owner only** for now (remote/phone = future), is mutually exclusive with auto-answer, and is bounded by a **30-min attended-operator watchdog** (`JTCAT_FULL_AUTO_CQ_WATCHDOG_MS`) — Part 97 keeps unattended automatic control off the FT8 calling frequencies, so this must not be run unattended. Retry policy is the pure, unit-tested `decideRetryOutcome()` in `lib/jtcat-state-machine.js`, executed by `jtcatHandleRetryStall()` in main.js (all four decode paths).

**Hunt and the watchdog (K3SBP 2026-09-16):** ULTRACAT is the operator taking full responsibility, so with it unlocked **Hunt runs as long as the operator leaves it on**. Without ULTRACAT, Hunt shares Run's clock (`jtcatFullAutoCqLastActivity`: operator action or QSO progress) and `jtcatFullAutoCqWatchdog()` turns it off via `setJtcatHuntMode('off')` after 30 minutes idle, which still lets a QSO in progress finish. Guarded in `test/jtcat-hunt-off-test.js`.

**Hunt ⇄ Run auto-switch (`jtcatHuntCqFallback`, default OFF, ULTRACAT-gated, KQ4MHD 2026-08-05).** What Chuck actually asked for — the drained-band pause below answers the opposite question. While **Hunt** is on, if nothing workable calls CQ for `JTCAT_HUNT_FALLBACK_PERIODS` (4 ≈ 1 min FT8) POTACAT starts calling CQ itself, and hands straight back to Hunt the moment a station matching the **suspended Hunt filter** appears. Hunt is preferred; Run only fills gaps. `jtcatHuntCqFallbackTick()` runs from every decode path *before* the Run-resume check, so a returning band goes to hunting rather than resuming CQ. Never switches mid-QSO (a live QSO resets the quiet counter). Non-obvious pieces, all load-bearing: (1) `startFullAutoCq(owner, modifier, {auto:true})` must NOT restamp `jtcatFullAutoCqLastActivity` or clear the worked-session set — restamping would let the loop transmit indefinitely unattended, which is the Part 97 line the watchdog holds; (2) so `setJtcatHuntMode()` stamps that clock instead (choosing a Hunt mode IS the operator engaging automatic operation), or the clock reads 0 and the watchdog kills the first fallback CQ instantly; (3) the handback must NULL the CQ QSO shell — `stopFullAutoCq` silences TX but leaves the object, and the Hunt selector refuses to engage while one exists; (4) the quiet counter is period-gated (`_jtcatHuntQuietPeriod`) or N slices reach the threshold N× too fast, while the *resume* check is deliberately un-gated so any slice can hand back; (5) `broadcastAutoCqState` reports `jtcatHuntFallbackMode || jtcatAutoCqMode` + a `fallback` flag, else the Hunt select snaps to "Off" whenever the band goes quiet. `setJtcatHuntMode()` is now the ONE operator-facing Hunt setter (popout, in-window, phone) and cancels a fallback Run — leaving Run keyed while the select reads "All CQs" would be a lie.

**Dupe-skip + drained-band pause (2026-08-05, W9TEF/K3SBP).** Two linked fixes; the first is the prerequisite for the second. (1) The cq-phase reply selection (`advanceJtcatQso`, `lib/jtcat-state-machine.js`) now takes an optional `deps.skipCall` predicate; main supplies it **only in run mode**, so a manual CQ still answers whoever calls (WSJT-X parity) and the double-click reply keeps its orange dupe toast. The predicate is `jtcatIsWorkedCall(call, band, mode)` — the ONE worked-before definition, shared with that toast via `jtcatWorkedInfo()`, band/mode aware because the same station on another band is a legitimate QSO. Without it Run re-worked the same callers forever and "drained" was not a state the code could recognise. (2) Run now **pauses** when nobody has answered for `jtcatRunPauseAfter` CQs **and** no unworked station is calling CQ, and resumes the instant one appears. Policy is the pure `decideRunCqPause()` (a deliberate *sibling* of `decideRetryOutcome`, whose "cq + runMode → continue forever" rule is asserted by tests and unchanged); execution is `jtcatPauseRunCq`/`jtcatResumeRunCq` in main.js. Both conditions are load-bearing — unanswered CQs alone would pause on a busy band where you're simply not being heard. "Workable" comes from `jtcatWorkableCallers()`, extracted from Hunt's candidate filter so both share one definition. **The 30-min watchdog stays armed while paused** (`jtcatFullAutoCqLastActivity` is not petted), so a dead band ends the run rather than leaving it armed. Also fixed here: both remote retry sites passed `runMode: false` from the popout-only era, so a **phone-owned run aborted on its first stalled QSO** instead of re-arming.
