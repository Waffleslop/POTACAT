# Special events are DATA, and a checklist station can be a PLACE

Recorded 2026-09-12. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**Special events are DATA, and a checklist station can be a PLACE** (Route 66 On The Air 2026-09-12; 13 Colonies inherits everything). An event is an entry in `https://potacat.com/events/active.json` (fetched at launch + every 4 h with `If-None-Match`, cached at `userData/events-cache.json`, **feed wins**) mirrored byte-for-byte in `BUILTIN_EVENTS` (main.js, the cacheless-fresh-install fallback and the definition of record). Deploy the feed ≥4 h before the opening and confirm the ETag changed, or running installs 304 forever; `scripts/validate-events.js <feed> --compare --require <ids>` asserts the two copies deep-equal and `test/events-catalog-test.js` runs the same rules on `BUILTIN_EVENTS` in CI (pattern set == checklist item id set, `total` == items, windows that parse with start < end, lat/lon in range, unique `route`). **Patterns are exact — never `W6*`** (`matchesEventPattern` is exact unless the pattern ends `/*`; a wildcard badges every California call). `contestId` goes ON the definition, not in `lib/event-registry.js BUILTIN_ALIASES` (Phase C retires it); a special event has no ADIF `CONTEST_ID` enumeration, so QSOs carry `APP_POTACAT_EVENT=<id>` + the `[Name - Item]` comment tag. Checklist items take optional, additive metadata — `lat`/`lon`, `route` (polyline order), `offRoute` (pin only), `group` (board sub-heading, e.g. Rovers) — and nothing is invented: a rover with no published coordinates is a heading, not a pin. Consumers, all generic: `lib/event-geo.js eventStationGeo()` places a cluster spot from a tracked station at the event's city with `coordSource:'event'`, which is **TERMINAL** (`refineClusterSpotWithQrz` returns early — the club station's QRZ address is somebody's house) and **not gated on opt-in** (location is a fact about the station, not a preference); the map overlay (`buildEventMapOverlay()` in renderer/app.js, geometry built once and riding the pop-out spot push so both windows draw the same thing; hollow pin = needed, filled = worked, dashed `badgeColor` route line over the tune arc's black halo; "Show on map"/"Hide from map" is device-local `EVENT_MAP_HIDDEN_KEY`); the board's `group` sub-headings and distance/bearing tooltip; the links row (`renderEventLinksRow`: Event site / Rules / Certificate application / Stations / Frequencies from `links`, `links.results` IS the award path and the finished lifecycle sentence links it) gated by `eventUrlAllowed()` — a URL an active event names is an allowed link-out for `open-external` and `open-contest-url`, so sponsor hostnames are never enumerated. **Hunt: Event stations** — `matchesHuntFilter(text,'event',{eventNeeded})` answers a `CQ` (only a CQ; never tail-end) from a station `eventDecodeMatch()` classifies as needed/new-slot, the same classification the popout badge shows; offered while `eventHuntAvailability()` (lib/event-decode-match.js) finds an opted-in checklist event within ±24 h `HUNT_GRACE_MS` — the grace arms the *control* the evening before and never widens matching. `jtcat-auto-cq-state` carries `eventHunt {available, events[{id,name,badge}]}` and is **hydrated at ECHOCAT connect and popout open** (`jtcatAutoCqStatePayload()`; `jtcatEventHuntSync()` re-broadcasts on flips from the events refetch, the 5-min boundary ticker and opt-in/out); popout + web client append/remove the `event` option like the Field Day option and keep it while selected. ECHOCAT catalog (`buildEventCatalogPayload`): `available[]` carries `badgeColor` + `links`, `subscriptions[]` also `url`/`badge`, `eventLinksForClients()` passes http(s) only; `tracking` passes through verbatim so item metadata reaches the mobile device with no new message. Deliberately unchanged: the Event Focus pill cap (`EVENT_CHIP_MAX_WINDOW_MS` 120 h — 13C at 159 h and Route 66 at 216 h both get the board's Focus Spots button, no pill; changing it needs a mobile twin). Dev-instance recipe for live checks without touching the running app: a second `electron . --user-data-dir=<scratch> --remote-debugging-port=9229` whose profile `settings.json` sets a different `remotePort` (7300 is held by the real instance) and the event `optedIn`; opt in/out from CDP via `window.api.setEventOptIn({eventId, optedIn})`.
