# Journal entries belong to an ACCOUNT, and sign-in asks the cloud what it is missing

Recorded 2026-09-18. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**Journal entries belong to an ACCOUNT, and sign-in asks the cloud what it is missing** (cloud handoff 2026-09-18). Every `sync-journal.json` entry carries `owner` = the server user id (`cloudUser.id`, else the access token's JWT `sub`, else email — `currentOwnerId()` in lib/cloud-ipc.js); the sync cycle is handed `journal.forOwner(owner)`, a view that sees only that account's entries, so on a shared shack PC one operator's QSOs can no longer be pushed into the next operator's cloud logbook (the server cannot defend against it — that push is correctly authenticated). Other accounts' entries stay parked and the Cloud card says "+ N waiting for another account"; signed out (`owner === null`) owns NOTHING — a legacy entry's owner is also null, and strict equality once handed those to nobody's push. Pre-stamp entries are adopted by the first account to push, once. **Catch-up:** `reconcileWithCloud(reason)` runs 1.5 s after any sign-in and once 15 s after boot: `QsoLog.ensureIdentities()` gives every local record a real uuid (missing, malformed, or duplicated → fresh, journaled as a create), then `POST /v1/sync/missing` (5000/batch, `CloudSyncClient.checkMissing`) says which local uuids the cloud lacks, those are journaled as creates for this account and pushed. A tombstone counts as held, so a QSO deleted on another device is never resurrected. **Never journal a malformed uuid:** `qsos.uuid` is a Postgres UUID column, so one bad id fails the cast, fails the whole push batch with a 500, retires nothing, and retries forever — `uuidOf()`/`isValidUuid` in lib/qso-log.js treat anything non-UUID as "no uuid" everywhere identity is decided. Log tells: `[Cloud] Catch-up (signin): 2 of 3 local QSOs are not in the cloud yet — queued for upload`. Tests: `test/cloud-log-sync-test.js` (ownership, adoption, catch-up against a fake /missing).
