# ECHOCAT Web over POTACAT Cloud — sign in at login.potacat.com, then a cookie, never a token box

Recorded 2026-09-11. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**ECHOCAT Web over POTACAT Cloud — sign in at login.potacat.com, then a cookie, never a token box** (2026-09-11, a BMAC donor away from the LAN). The tunnel (`<callsign>.potacat.com` → desktop :7300) used to answer every anonymous HTTP request with the e696ad5 503 stub, so only the mobile app could use it. Now anonymous `GET /` (and `/remote.html`) on the tunnel is a **constant** static connect page from `buildConnectPageHtml()` in `lib/echocat-web-gate.js` — no template inputs, so it cannot leak the version/callsign/source the stub was introduced to hide; every other unauthenticated tunnel path is still the stub. Auth is an HttpOnly cookie: `__Host-echocat_device` minted by `POST /api/pair-account {pairToken, web:true}` (the device token is omitted from the JSON; the browser becomes a `platform:'web'` paired device named from its User-Agent, revocable in My devices) or `__Host-echocat_pass` from `POST /api/pass-gate {passCode, sessionId}` (the existing `_passValidator`; Max-Age bounded by the pass expiry, ≤7 d; `broadcastPassEnded` purges the map). **`decideHttpGate` and `wsAuthModeFor` in `lib/echocat-web-gate.js` are the ONE HTTP/WS auth-mode decision** — the 2026-06-13 dead-shell regression came from the two drifting — and the web client (`renderer/remote.js`) treats `__authMode="cookie"` + `auth-mode: token` as a dead cookie: `webSignOutAndReload()` → `POST /api/web-signout` (clears both cookies, revokes a web device) → `/?notice=…`, with a sessionStorage loop-breaker. Every cookie-authenticated WS upgrade and every browser-only endpoint requires `Origin` = `Host` (or the tunnel `cloudHost`) — `originAllowed()` — because a hostile page can make the browser attach the cookie; the `__Host-` prefix defeats cookie-tossing from sibling `*.potacat.com` stations; tunnel-sourced POSTs are rate-limited by `cf-connecting-ip` (`FailureRateLimiter`, cloud `rateLimitPasses` tiers). The sign-in page is the cloudlog repo (`routes/login-host.js`, `public/login.html` + `login.js`): the same Express app host-matched on `login.potacat.com` (own origin so its 365-day refresh token in localStorage is unreadable from the api host; every `/v1` call same-origin, no CORS), strict CSP with no inline script, an allow-list where everything else 404s, and it navigates ONLY to a `cloud_host` from the account's own shack list or the redeem reply (open-redirect guard). Owner: `POST /v1/devices {type:'client', platform:'web'}` → `POST /v1/devices/:shackId/authorize` → `https://<host>/#pair=<pairToken>` (60 s, single-use, fragment-only). Guest: `guest-pass.html` "Open in your browser" → `redeem-anonymous` (cached — a second anonymous redeem mints a new synthetic user and is refused) or `login.potacat.com/?pass=` → `redeem` → `#pass=<code>.<session_id>`. `callsignToHost` refuses reserved labels (`login`, `api`, …). Deploy needs Cloudflare DNS `login` (proxied), nginx `server_name` including `login.potacat.com`, and an origin cert covering `*.potacat.com`. Tests: `test/echocat-web-gate-test.js` (pure), `test/tunnel-webui-gate-test.js` (live server), cloudlog `scripts/test-login-host.js` (Host-matched via `http.request` — undici `fetch` drops a caller-supplied Host header).
