# CI-V DATA mode is two bytes, and a three-DATA Icom re-selects the D-number the radio reported

Recorded 2026-10-16. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**CI-V DATA mode is two bytes, and a three-DATA Icom re-selects the D-number the radio reported** (WF4I IC-7610 #96/#97, 2026-10-16). `1A 06` is [data, filter]: 00 OFF / 01-03 = DATA1/2/3, filter 01-03, and the reference guide says "when 00 is set, also set 00 to the filter". POTACAT sent the one-byte form (`01`/`00`), which the IC-7300/7100 tolerate and the IC-7610 does not: a lone `01` was not taken as a DATA set (JTCAT left USB-D2 as plain USB, no error anywhere) and a lone `00` on every tune reset the filter to FIL1. `civ-codec.js setMode` now sends `1A 06 00 00` / `1A 06 <D> <fil>`, the controller polls `getDataMode()` on the slow cycle (`rx: DATA mode DATA2 FIL2` on change; three NAKs with no reply ever = latched off for the connection), and **per-mode filter memory** (`_filterByMode`, USB and USB-D separate) puts the TARGET mode's own last-reported FIL in cmd 06 instead of the current mode's (CW FIL3 used to ride into an SSB set). IC-7200 uses sub 04 (`civDataModeSub`). Hamlib only ever sends DATA1 — do not copy that; WF4I runs FT8 on D2. Icom's own site refuses scripted downloads; the IC-7610 guide is mirrored at radiomanual.info. Tests: `test/rig-test.js` "DATA mode is two bytes".
