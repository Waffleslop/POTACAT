# Icom Network addresses the radio the radio names, and the RS-BA1 glue's methods must exist

Recorded 2026-09-14. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**Icom Network addresses the radio the radio names, and the RS-BA1 glue's methods must exist** (K3FZT/W3AOK IC-7760, 2026-09-14). `codec.setRadioAddress`, `controller.getDataMod`, `controller.setDataMod` were called by main.js from the day Icom Network shipped and never existed: Test Connection threw inside a timer (uncaughtException → fatal dialog + exit) and DATA MOD auto-LAN logged "CI-V settings commands are unavailable" on every connect. They live in `lib/codecs/civ-codec.js` (cmd `1A 05` + two-byte BCD item id, `data-mod` parse) and `lib/rig-controller.js`; `test/rig-test.js` carries source-text guards so call sites and methods cannot drift apart again. **An Icom ignores any frame not addressed to it**, so a wrong CI-V address is a perfect session with a silent radio and nothing in the log: the live address used to come ONLY from `rigs[].model` (generic Icom = 0x94), so `getActiveRigModel` now borrows `catTarget.civAddress` from the Radio Model picker, and the Icom Network path adopts the address the radio reports in its Capabilities packet (`rsba1-transport` `radio-info`, `[Icom Network] radio reports CI-V address 0xB2 …`), which Test probes first. Set-mode item ids are PER MODEL (the same number is an unrelated menu item on another radio) — `ICOM_NETWORK_DATA_MOD_SPECS` in main.js is the only place they are declared (IC-7760: item `0x0130` DATA1 MOD, LAN = `0x09`; DATA2/DATA3 have their own sources, so a second program on USB can coexist). `getModel()` returns the shared table object — never mutate `civAddr` on it.
