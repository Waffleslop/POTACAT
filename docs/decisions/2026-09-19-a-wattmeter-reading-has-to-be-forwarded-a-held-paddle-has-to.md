# A wattmeter reading has to be forwarded, a held paddle has to keep keying, and a scrolling toolbar must never change its own overflow

Recorded 2026-09-19. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**A wattmeter reading has to be forwarded, a held paddle has to keep keying, and a scrolling toolbar must never change its own overflow** (LZ3AW round 5, 2026-09-19, on 1.10.18). (1) `RigController` listened for the codec's `powerMeter` event nowhere, so every direct-serial and rigctld rig emitted watts that died inside the controller — main.js subscribes to the CONTROLLER, and the 1.10.18 fan-out only ever had a source on the Flex path ("there is a bargraph, but not moving"). It now re-emits and counts as a live read. A radio that answers no CAT during TX says so once in the log (`no meter reply while transmitting`), because on such a link the meter CANNOT work and silence looked like a bug. The web PWR bar lives in the meter strip behind a checkbox that said "Show S-Meter / SWR" — it names every meter now. (2) **The ECHOCAT paddle watchdog re-armed only on paddle MESSAGES**, and a held contact sends exactly one: the keyer was stopped 1.5 s into any squeeze or long string, which is the TinyMidi "stops after a few seconds" that survived the 1.10.18 CW-hold fix. Clients now repeat a held contact (`hold: true`, 400 ms) and keep the strict window; clients that do not (native app, older builds) re-arm it from the keyer's own key events, bounded by the keyer's 10 s max streak. (3) `noteTransmitting(ms)` EXTENDS, it no longer stacks — every paddle edge added 2 s to a running total, leaving a rig flagged as transmitting for minutes after an over (PTT held, staleness watchdog exempting a dead link); `{queue:true}` is the one stacking caller, the rig's own KY buffer. (4) Opening a web dropdown set the toolbar to `overflow-x:visible`, which RESETS `scrollLeft`: on a phone the bar jumped, the tapped button slid away and the bar froze ("the whole bar line stucks") — the open panel is moved to `<body>` now (`openDropdownPanel`, shown by its own `.rc-open` class) and the bar is never touched. (5) Custom **slider** slots are drawn in both VFO surfaces (the desktop pop-out builds a real one, the web pane mirrors the overlay's and drives the source input so debounce and substitution stay in one place); `customSliderCommand` now has THREE copies, all pinned by `test/custom-cat-parity-test.js`. (6) The web hunt matcher kept a hand-rolled callsign scraper that never stripped hash brackets, so a hunted station decoding as `CQ <SP9ABC/P>` was the one station the web would not answer — it uses the shared parser now. Tests: `test/lz3aw-round5-test.js` (live keyer timing for the paddle, real codec→controller meter event, hold semantics, source guards).
