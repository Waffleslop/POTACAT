# A CW message holds `_transmitting` for its envelope, and Kenwood `IF;` P8 is the radio's PTT

Recorded 2026-09-14. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**A CW message holds `_transmitting` for its envelope, and Kenwood `IF;` P8 is the radio's PTT** (LZ3AW TS-480, 2026-09-14 → fixed 2026-09-18). The radio keys ITSELF from its KY buffer, so `setTransmit()` never ran for CW text and the paddle's `TX;`/`RX;` went straight to the codec: `_transmitting` stayed false through every over. A TS-480 mutes CAT while transmitting and `_checkPollStaleness` exempts only `_transmitting`, so ten seconds of a CQ — or a few seconds of key-as-I-type — declared the link DOWN and every later keystroke was refused ("after several seconds the radio stops transmitting"). `RigController._holdTxForCw(text)` marks TX for `12000/wpm` ms per character, extends on each append, and restarts the no-reply window when the hold ends; `_cwHoldExpired` defers to a CAT readback that says still-keyed, and an RX readback (`kenwood-codec` `IF;` index 28 → `'ptt'`) ends the hold immediately. **In live mode Enter/Send only clears the box** (desktop `cwMacroInput`, web `cwTextSend`): handing the line to Send sent `RX;` — aborting the letters still keying — then replayed the whole line, and on the web left `cwLiveSent` at the old length so the next characters were swallowed. Tests: `test/cw-live-watchdog-test.js`. **TS-480 SSB/FM width = `SH` high cut over the operator's `SL` low cut, never `FW`** (`slopeFilters` on the model, tables verbatim from hamlib `ts480_slope_filter_high[]/_low[]`; `_setSlopeWidth` picks the first high cut ≥ low + width like hamlib's `find_slope_filter_for_frequency`, reads `SL;` and never moves it, emits the ACHIEVED `passband`; `SL;`/`SH;` polled every 5th cycle via `codec.getFilter()`). In SSB `FW` only chooses between fitted IF filters — the one stock slot is 2400, so two earlier "snap to a real slot" fixes were correct and still did nothing. **A measured wattmeter never rides the power-SETTING channel:** `cat.on('powerMeter')` → `sendCatFwdPower()` (the one fan-out the Flex TX bridge uses; `cat-fwd-power`/`fwd-power`, decays to 0 after 3 s), not `sendCatPower` where `PC;` overwrote it and nothing drew it; TS-480 meter query is `SM0;` (`model.smQuery`, hamlib). **The spot check mark = worked on this BAND and MODE** (`hasWorkedOnBandMode` in app.js and remote.js; `lib/adif.js normalizeMode(mode, submode)` names logged modes the way spots do — USB/LSB→SSB, MFSK/FT4→FT4 — in `parseWorkedQsos` AND both live-add sites in main.js, or a logged USB never matches a spotted SSB). **Web quick log follows the dial** (`quickLogFollowRadio`, own dirty flags; a spot-opened hunter sheet is pinned only until the radio arrives within 500 Hz). **Custom CAT editor on the web must never rebuild itself from its own `focusout`** (`renderCustomCatButtons({keepEditor:true})`, in-editor focus moves ignored) — that is how a toggle's Off command could never be typed and every toggle saved with an empty Off; toggle state survives settings pushes for unchanged slots; the VFO pop-out honours `type:'toggle'`. **CW `{call}` = the callsign most recently typed in ANY field on ANY surface** (`lib/typed-call.js` `TypedCallTracker`, one instance in main.js; `setTypedCall(source, call)` broadcasts the winner on `log-popout-callsign` to the window + VFO pop-out and as S2C `typed-call` to ECHOCAT, hydrated at connect and pop-out open). Every field reports on typing AND on code fills/clears (`reportLogCallsign(v, source)` / pop-out `reportCall()` / web `reportTypedCall(source, v)`), a closed window reports `''`, and every expander prefers the merged value, then its own live fields, then the tuned spot — never a local field first (that is how a stale panel box beat the call just typed into the log sheet). Round 4 of LZ3AW's list is now fully built; his on-air confirmation is the remaining step. **Round 4b (his 9/18 bug report):** his CW text goes out on the **CW Key Port (DTR keyer, COM4)**, not the rig's KY buffer — `[CW] Text via DTR keyer` is the tell — and `sendCwTextViaDtrKey` cancelled every in-flight timer per call, so each live character killed the one before it (slow typing worked, fast typing "useless"); live sends now APPEND at `_cwDtrQueueEndAt` (`{ live }` reaches the key port). Both DTR paths (text queue length, paddle edges +2 s) call `cat.noteTransmitting(ms)` — the public form of the CW hold — so a CAT-muted TS-480 is not declared DOWN mid-over, which forced the key line low and was his TinyMidi paddle "stops after a few seconds". JTCAT `parseCq` strips hash brackets (a `CQ <SP9ABC/P>` decode never keyed; an unresolved `<...>` is still refused). Manual entry takes a UTC date/time: desktop New QSO (pre-filled now) and the web Log tab (blank = now, both filled = past QSO via `qsoAt`). **Callsign filter** on both spot lists: `lib/call-filter.js` (prefix tokens, `*`/`?`, device-local) with a VERBATIM copy in remote.js pinned by `test/call-filter-test.js`. **Hunt (activator split) always shows the spots table**: `applyActivatorSpotsLayout` calls `setView('table')` when `currentView` is an exclusive view (directory/RBN/DXCC/contests) — the lower pane renders `currentView`, so SWL/HF Nets opened before activator mode came back in place of spots. **QSO-logged chime** (`settings.qsoChime`, default `'off'`, N2FSM): main emits `qso-logged` from `saveQsoRecord` — the one choke point every log path passes through — and `playQsoChime()` in app.js synthesizes it (no audio asset); any new "a QSO was logged" UX should hang off that same event, never off one log path. **Every JTCAT decode carries `slot`** (K4HXM 2026-09-18: Hunt "often" transmitted in the activator's own slot — the batch had a slot, the results did not, `caller.slot || 'even'` always replied on odd = a coin flip per activator). `Ft8Engine` records the slot per decode JOB at post time (`_decodeJobSlots`) and stamps each result from that on arrival — never from `_lastRxSlot` at arrival, which a slow decode can outlive — and the snapshot slot comes from WALL time (the adjusted clock crosses the boundary under a negative latency calibration). Consumers may fall back to `ft8Engine._lastRxSlot`, never to a literal parity. `lib/ft8-engine-test.js testDecodeSlotStamp`.
