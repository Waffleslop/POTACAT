# A spot's Log button follows the standalone Log QSO window

Recorded 2026-08-05. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**A spot's Log button follows the standalone Log QSO window** — if the Ctrl+L pop-out is open, `routeLogForSpot()` (renderer/app.js) sends the spot there (`log-popout-open` already focuses an open window and re-sends the prefill) instead of stacking the in-window `#log-dialog` overlay on top of it; closed pop-out = overlay, unchanged. No setting: opening that window IS the opt-in (W9TEF 2026-08-05, who keeps it on a second screen). **It falls back to the overlay whenever the spot needs it** — `spotFitsPopout()` refuses n-fers (2+ programs), comma-separated multi-park refs, WWBOTA (no chip in the pop-out) and Ctrl-select multi-op — because the pop-out's one-chip/one-ref form would silently drop that log data. Program detection is the shared `detectSpotPrograms()`, used by BOTH the overlay and the router so they can't drift. Spot-driven prefills carry `force: true`, the only path allowed to overwrite what's already typed (`applySpotPrefill` in renderer/log-popout.js resets the form first — a Log click is deliberate); the plain Ctrl+L prefill still defers to entered values. `log-popout-status` mirrors the other popout status channels and is ALSO replayed on the main window's did-finish-load (this pop-out re-opens itself at startup, so it can exist before the renderer does).
