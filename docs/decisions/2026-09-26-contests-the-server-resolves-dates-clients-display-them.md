# Contests: the server resolves dates, clients display them

Recorded 2026-09-26. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**Contests: the server resolves dates, clients display them** (2026-09-26, Casey: "cron on the server … push updates to desktop and mobile"). `data/contests.json` is the ONE catalog (edit it + push master = every user within a day). api.potacat.com runs `scripts/refresh-contests.js` (potacat-cloudlog, systemd timer daily 06:00 UTC, `install-contests-refresh-timer.sh`) with a VENDORED copy of `lib/contests-db.js` — re-copy it into cloudlog `lib/` and redeploy whenever the resolver's grammar changes. The job fetches the catalog from raw.githubusercontent, runs `validateCatalog()`, resolves occurrences (`parseRule().kind`: annual 400 d, weekly/monthly 60 d; `custom:` only via `explicitWindows`), checks links weekly (dead = two consecutive 404/410/DNS; 403/406/429/5xx never), refuses to publish on any failure or a >20% shrink, serves `GET /v1/contests` (ETag/304). Desktop: `lib/contests-feed.js` (fetch 20 s after launch + every 6 h, cache in userData, next = first occurrence with end > now, per-entry fallback to the bundled resolver, dead rulesUrl → website) and `contestsCatalog()` in main.js is the only catalog reader (view, link allowlist, event aliasing, history). Mobile handoff: potacat-app `docs/desktop-handoffs/contests-feed.md`. Contract: `docs/contests-feed.md`. A tracked EVENT (America250) must not also be a catalog entry — it renders its own row. Tests: `test/contests-db-test.js`, `test/contests-feed-test.js`, cloudlog `scripts/test-contests-feed.js`.
