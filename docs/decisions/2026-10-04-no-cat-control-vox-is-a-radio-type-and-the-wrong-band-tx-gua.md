# "No CAT control (VOX)" is a radio type, and the wrong-band TX guard trusts only a LIVE dial

Recorded 2026-10-04. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**"No CAT control (VOX)" is a radio type, and the wrong-band TX guard trusts only a LIVE dial** (N4FFF's Pebble HF, 2026-10-04 — a uSDX kit with no CAT port, VOX-keyed; first on-air JTTY QSOs the same evening on his IC-705). Rig editor radio `nocat` → `catTarget {type:'none'}` (a REAL target, so the rig activates like any other); `connectCat` opens nothing and logs one plain line (`sendCatStatus({connected:false, noCat:true})` → neutral pill, no red, no disconnect toast); `handleRemotePtt` logs `[PTT] TX — no CAT control, the radio's VOX keys on the audio` instead of PTT FAILED; both tune refusals say `No CAT control — set the radio to X MHz by hand`; `lib/rig-family.js` 'none', `radioTypeFromCatTarget` 'nocat', station-setup radio-control = ok and the transmit test becomes **a 3 s tune tone + "The radio keyed"** (`tune-tone` action → `startJtcatTune({toneHz:1500})`, confirmation = the existing `tx-test-confirm` → state `confirmed`). **Pebble HF is a model** (`RIG_MODELS['Pebble HF']`: brand Ham Radio Duo, `protocol:'none'`, `noCat:true`, `bands:['20m']`, 5 W); `getModelList()` carries a per-brand `noCat` list so picking the model selects "No CAT control (VOX)" by itself; `rig-setup-notes` `pebble-vox-audio`; `noCatBandNote()` appends "— Pebble HF is 20m only" to a tune refusal off-band. Welcome wizard offers the type too. **The FT8/JTTY wrong-band guard** (`_jtcatExpectedDialHz` vs `_currentFreqHz`) now requires `dialLive` (CAT connected or SmartSDR) — with no link `_currentFreqHz` was the PREVIOUS rig's dial and blocked every Send with nothing visible in a keyboard-mode pane; `connectCat` also zeroes `_currentFreqHz` when it drops a rig. `test/nocat-rig-test.js`. Welcome wizard does not offer the type yet.
