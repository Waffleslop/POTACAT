# The Cloud Tunnel's "Live" means POTACAT is answering behind it, not just that cloudflared is connected

Recorded 2026-09-17. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**The Cloud Tunnel's "Live" means POTACAT is answering behind it, not just that cloudflared is connected** (K5AWJ 2026-09-17: tunnel healthy with 4 connections, `k5awj.potacat.com` 502 for hours, app showing green). cloudflared is our child process, so a healthy tunnel proves the app was up — the LOCAL server on :7300 was not answering, and nothing looked: `started` had no listener, the bind retry gave up into a log line, and a cert failure fell back to plain HTTP with only `console.warn`. Now `lib/origin-health.js` owns the decision (`decideOriginState`, pure) and the one real request (`probeLocalOrigin`, HTTPS with verification off, exactly as the ingress does; a TLS failure is retried as plain HTTP so "serving HTTP" is told apart from "nothing there"). `CloudTunnelManager` runs it after every healthy tick and on `recheckOrigin()` (main calls that from `remoteServer.on('server-state')`, so the card flips within a second of a bind, not at the next 5-min tick — the tick cadence itself is a cost guardrail, never shorten it). The result rides `getState().origin`; only `origin.state === 'ok'` earns a green pill and a clickable `<callsign>.potacat.com` link (cloud-ui.js, app.js web block, tray). **The ingress is fixed SERVER-side at `https://localhost:7300`** (cloudlog `routes/cloud-tunnel.js DESKTOP_HTTPS_PORT`, mirrored as `TUNNEL_INGRESS_PORT`) while `settings.remotePort` is user-editable — a changed port is a permanent 502 with a healthy tunnel, so it is the FIRST state the decision names. `RemoteServer.serverState()`/`'server-state'`: bind failure keeps retrying every 30 s after the 5 fast attempts (a stale process usually exits within minutes) and is a sticky `app-notice`; a missing TLS cert is **refused outright while the tunnel is exposed** (an HTTP origin behind an https ingress can only 502) and allowed-but-logged on a LAN-only station; `getOrCreateTlsCert` reports its failure through `opts.onError` so the reason reaches `session.log` and bug reports (`**ECHOCAT server:**` line, `connection.localServer` + `cloudTunnel.origin` in the snapshot — additive, the mobile assembler's seven-section shape is unchanged). Found underneath: `ws` re-emits the HTTP server's `'error'` on the WebSocketServer, which had no listener, so a busy port threw an uncaughtException before the retry loop ever ran. **Login items are opt-in (Casey, 2026-09-18):** the Remote Launcher's boot re-assert runs only on `settings.enableLauncher === true`; the Install/Uninstall buttons in Settings > ECHOCAT persist that flag (the old `#set-enable-launcher` checkbox is a null stub — `app.js` must never write `enableLauncher` from it again, which is how every Settings save used to flip it false while the login item stayed). Never add `launchAtStartup` or the launcher silently: the Cloud tab OFFERS both while the tunnel is on and POTACAT is not a login item (`refreshStartupOffer`, `#cloud-tunnel-startup`, "Not now" = this session only). The launcher is reachable only on the LAN/Tailscale (port 7301 is not behind the tunnel — deliberately: its auth is `Bearer <callsign>`, a public string). Tests: `test/launch-origin-test.js` (live probe against real HTTPS/HTTP listeners, held-port retry, cert-dir-is-a-file refusal, manager wiring, source guards).
