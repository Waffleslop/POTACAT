# The activation's own program is STORED, never inferred at log time

Recorded 2026-03-01 (date is when the note was written, taken from the text or the nearest release). Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**The activation's own program is STORED, never inferred at log time** — `lib/activation-program.js` (pure, dual-mode UMD + `test/activation-program-test.js`) owns `inferParkProgram`/`normalizeParkRefs`/`primaryProgram`/`activationMyRefs`/`myRefKeys`, and `activatorParkRefs` entries are `{ref, name, program}`. `MY_SIG` used to be the literal `'POTA'` in **eleven** places across `renderer/app.js` and `main.js`, so a SOTA/WWFF/LLOTA/WWBOTA activator got `MY_SIG=POTA` on every contact — invisible until an award check failed. **Why stored and not derived: `inferParkProgram()` cannot see LLOTA.** `LLCL-0001` is structurally identical to a POTA ref `US-0512` (same for PARC's `US-NC-2540`), so inference is safe as a *seeder* at ref-entry time — when the operator can still see and correct it — and never as the source of truth. The governing safety property is that **anything missing or unrecognised resolves to POTA**, applied at read time at every log-building site, so an unmigrated setting keeps the old behaviour byte-for-byte. Renderer and main must land together: half-landed, SSB logs the right program while FT8/JTCAT/phone log POTA — a split log, worse than consistent-wrong. `test/activation-log-test.js` carries a **source-text guard** asserting no `mySig: 'POTA'` survives in either file; that is what enforces the atomicity. Also fixed here: `resumeActivation` discarded `r.sig` (which is `MY_SIG` read back out of the operator's own ADIF, so it needs no inference at all); the phone's `set-activator-park` had always carried `sig` and main never read it; the phone cross-product gate compared `mySig === 'POTA'` and so skipped multi-park entirely for a SOTA activation; and dead `writeActivationAdif` (zero callers — every export uses `writeActivationAdifRaw`) was deleted rather than fixed. **`activationMyRefs` dedupe is load-bearing, not tidiness:** before the fix a SOTA activator had to enter the summit *twice* — primary field (logged POTA, wrong) plus X-Ref slot (logged SOTA, right) — and their upload worked only because of that second record; once the primary reports its real program those become the same record, and `_qsoDedupKey` deliberately includes `mySigInfo` so genuine n-fers survive and would not catch it. **Release-note consequence:** existing non-POTA activators see records-per-QSO drop from two to one, and a log holding both pre- and post-fix records for the same ref on the same day surfaces as two past activations (`getPastActivations` groups on `ref|date`).
