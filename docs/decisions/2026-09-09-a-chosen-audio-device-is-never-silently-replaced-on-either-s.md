# A chosen audio device is never silently replaced — on EITHER side of the radio

Recorded 2026-09-09. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**A chosen audio device is never silently replaced — on EITHER side of the radio** — `renderer/remote-audio.html` (input, N2FSM 978ac10) and `renderer/app.js` `playJtcatTxAudio` (output, NA7C 2026-09-09) both REFUSE when the configured device id can't be opened, and say so on screen, not just in the log. The JTCAT renderer TX route used to log `[JTCAT TX] WARNING: setSinkId failed` and play the FT8 envelope to the system default anyway, with PTT already asserted by main: keyed radio, 0 W, no SWR, FT8 tones out of the PC speakers, WSJT-X (which picks its device by NAME each launch) working first try — and no on-screen tell for three weeks. Now a configured non-`alsa:` id whose `setSinkId` throws drops PTT immediately (`jtcatTxComplete`) and sends `jtcat-tx-audio-fault` → main logs `[JTCAT TX] TX refused: …` (`lib/jtcat-tx-audio-fault.js`, pure/tested wording) and pushes `jtcat-qso-state {phase:'error'}` to the popout + remote clients and `app-notice` to the main window. Deliberately NOT refused: raw ALSA ids (KF1G — his default WAS the rig), an UNCONFIGURED output (default + warning, some stations run the CODEC as the Windows default), and the Windows role devices (warning only, set-audio-device already refuses to store them). Never pre-check with `enumerateDevices` — it misses ids `setSinkId` accepts ("label unresolved, sink applied"); the real `setSinkId` throw at TX time is the only ground truth, and re-plugging the device self-heals because every cycle retries. **The tell for a stale saved id on BOTH sides:** "no audio on the phone since 1.10.13" (the bridge refusal) together with "FT8 keys but 0 W" = re-pick Input AND Output in Settings > My Rigs > Audio. Guarded by `test/audio-capture-device-test.js` (both sides, one rule).
