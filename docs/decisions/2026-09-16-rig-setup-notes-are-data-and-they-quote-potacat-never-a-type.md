# Rig setup notes are data, and they quote POTACAT, never a typed value

Recorded 2026-09-16. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**Rig setup notes are data, and they quote POTACAT, never a typed value** (K3SBP 2026-09-16, an FTDX10 whose CW was silent until MENU > CW SETTING > PC KEYING matched POTACAT). `lib/rig-setup-notes.js` is the table (scoped by model / brand / rig-editor radio type / platform; level required|recommended|tip; `source` names who reported it). A value POTACAT chooses is a `{placeholder}` filled by `resolveSetupNotes()` from the SAME resolver the keying code uses (`{mainKeyLine}` = `resolveCwKeyPins`, `{keyPortLine}` = `resolveKeyPortPins`, `{civAddr}` from RIG_MODELS as the menu shows it, "94h"), so the note follows the CW keying line dropdown and can never disagree with what main.js drives — the FTDX10 note says DTR on Auto and RTS when the rig is set to RTS. Resolved in main (`get-rig-setup-notes`, `rigSetupNotesFor`; Icoms count `catTarget.civModel` as the model), rendered by the rig editor's "Setup instructions" button (red + "N required" until ticked; auto-opens once on Add Rig), ticks stored as `rig.setupDone[]`, listed in every bug report (`**Setup notes:**`), and `activeRigSetupPointer()` appends the note title to the CW keying-route log lines. The FTDX10 default key line was deliberately NOT changed (Auto = DTR on the key port): changing it would break owners whose radio already matches. Only add a note a real station confirmed; `test/rig-setup-notes-test.js` checks models/brands/radio types exist, every placeholder fills for every model, and the Icom pickers agree with RIG_MODELS civAddr.
