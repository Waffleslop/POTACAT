# Station Setup: one checklist per radio, every tick MEASURED

Recorded 2026-09-24. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**Station Setup: one checklist per radio, every tick MEASURED** (Casey 2026-09-24: "so an 80-year-old ... can get set up quickly ... I won't hear any support tickets"). `lib/station-setup.js` is the whole policy (pure, `test/station-setup-test.js`): `evaluateChecklist()` turns what main gathered (`stationSetupLive()` in main.js) into steps — identity, radio control, hearing the radio (3 s listen on the rig's input, -80/-50 dBFS lines), audio to the radio (`setSinkId` on the rig's output — never an enumerateDevices pre-check), test transmit, clock, CW keying (only from a confirmed `rig-setup-notes` entry), FT-710 band scope. States ok / confirmed (operator vouches for an unreadable menu setting — never the measured tick) / needs / unknown / blocked / optional / skipped. **Menu paths come ONLY from lib/rig-setup-notes.js** — a guessed instruction manufactures the ticket this exists to prevent. **Test transmit** (`runStationSetupTxTest`, operator button + in-window antenna/dummy-load warning, never automatic): note power, drop to min(5 W, model maxPower), 3 s tune tone down the FT8 audio route (`startJtcatTune`), peak fwd power/SWR, restore, and believe only a READBACK (`_lastPowerReadback`); an unconfirmed restore persists `settings.setupTxPowerRestore` and `stationSetupReconcilePower` (in `sendCatPower`) repairs it — the WSPR-cap lesson. **Launch card** (`renderer/station-setup.js`, 12 s after launch so a connecting radio is not "unfinished"): only required steps that have NEVER passed (`rig.setupPassed`, first-pass timestamps) — a switched-off radio never nags; `rig.setupChecklistHidden` = "Don't ask again" (still reachable: More menu, Settings sidebar). **"New for your radio"**: a step's `since` version vs `_stationSetupLaunchLastVersion` (read at settings load, before What's New rewrites lastVersion), shown once (`rig.setupAnnounced`). **FTDI LibFT4222**: "Find the file for me" validates the PE machine (32-bit copy refused with "choose the amd64 one") and copies into `userData/ftdi`, which `startYaesuScope` prepends to PATH / LD_LIBRARY_PATH / DYLD_LIBRARY_PATH — no admin, survives updates, no C change. **Rig-list saves:** the renderer saves its whole `currentRigs` copy, so main's save-settings carries forward `setupPassed/setupSkipped/setupChecklistHidden/setupAnnounced` when an incoming rig lacks them, and the checklist refreshes `currentRigs`' setup fields after every action. Bug reports carry a `**Station Setup:**` line. Add Rig opens the new radio's checklist. **Share my working setup** (`lib/setup-share.js`, pure, `test/setup-share-test.js`; Casey 2026-09-25 "pull settings from users who actually use POTACAT"): offered at the end of the checklist ONLY when every required step works — a report is evidence a setup works, and broken setups already reach us as bug reports. The payload is an ALLOWLIST (`CAT_FIELDS`; audio device LABELS resolved by the renderer, never ids; callsign only when ticked; never host/port/path/user/password/rig name) and every field needs a `describeShare()` preview line — a test fails when one is added without it. Main builds preview and send from the ONE function `stationSetupShareBuild`, so the operator reads exactly what is posted. The operator's free-text `menuNotes` is a CANDIDATE for rig-setup-notes, never an instruction until a person confirms it. POST `https://api.potacat.com/v1/setup-reports` (anonymous; `POTACAT_SETUP_SHARE_URL` overrides for dev): ONLY 400/413 drop a report; everything else (no network, 404 = route not deployed, 429, 5xx, Cloudflare 403/52x) is kept in `settings.setupSharePending` (GLOBAL_KEY, newest per `rig.setupShareId`, 30-day cap) and retried 90 s after launch, 2 s apart (per-IP limit 10/h). The numbers behind a passing listen/test transmit persist on `rig.setupMeasured` so a "Worked on <date>" step still reports them; `measured.txTestEvidence` = measured|operator|unrecorded. Audio labels with a possessive ("Casey's AirPods") are withheld whole.
