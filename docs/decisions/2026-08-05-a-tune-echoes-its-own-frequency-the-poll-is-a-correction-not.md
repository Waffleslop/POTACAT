# A tune echoes its own frequency — the poll is a correction, not the source

Recorded 2026-08-05. Moved verbatim from the desktop CLAUDE.md on 2026-11-09; the original is archived in the potacat workspace at docs/history/CLAUDE-desktop-2026-11-09.md.

**A tune echoes its own frequency — the poll is a correction, not the source** — `tuneRadio()` calls `sendCatFrequency(tuneFreqHz)` + `sendCatMode(resolvedMode)` right after `cat.tune()`. The SmartSDR branch has done this since Flex Direct (it has no CAT poll at all); the CAT branch relied entirely on the frequency poll to echo the new VFO back, so **the VFO window showed the OLD frequency for as long as the poll took, and indefinitely whenever the poll wasn't running** — `settings.idlePauseMin` (default 20 min) *stops polling outright*, and a stale link or busy serial sandwich delays it (N2FSM IC-7300, 2026-08-05: QSY'd through spots, radio moved and the callsign/park text updated, VFO window sat on the session's first frequency). The poll still wins on disagreement, so an unconfirmed tune shows the target then reverts — the same optimistic pattern the VFO pop-out already uses for its own dial (`_freqSuppressTarget`). Note `tuneFreqHz` includes CW XIT, which is what the radio is really on.
