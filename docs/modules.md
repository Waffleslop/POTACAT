  js8call-config.js  — READ-ONLY reader for the operator's JS8Call.ini + `diagnoseJs8Config()`. POTACAT **bridges** JS8Call over its TCP API and never decodes JS8 itself: JS8Call is GPLv3, so a socket is mere aggregation while a `lib/js8_native/` codec from its sources would relicense the Apache-2.0 app (docs/digital-modes-plan.md's native JS8 plan is SUPERSEDED for exactly this). **Never writes the ini** — it's Qt QSettings with escaped `@Variant` binary blobs and `@Invalid()` markers that a generic INI library corrupts, and Qt rewrites the whole file on exit so anything written under a running JS8Call is reverted. Diagnoses in severity order: `blocker` (TCP API off — the default!), `conflict` (same Flex slice / same DAX RX channel as POTACAT), `notice`, `warn`. **Only a blocker refuses the connection.** Auto-reply and heartbeat are `notice`: refusing would not prevent one transmission (JS8Call keys whether or not we're attached) and would only blind us to transmissions that happen anyway — connecting is strictly SAFER. `js8MayTransmitUnprompted()` is the signal for code that must assume TX at any moment. (K3SBP's own station presented with all five problems at once.)
  js8call-client.js  — JS8Call TCP API client (newline-delimited JSON, port 2442). Resilience modelled on MercuryClient/DxClusterClient; the liveness watchdog PROBES (`STATION.GET_STATUS`) rather than assuming, since a quiet band and a half-open socket are identical. Deliberately incurious about message types (forks/versions differ — the build tested against is "JS8Call-improved" 2.4.0) EXCEPT TX state: pure `txStateFromMessage()` reads three independent signals (`RIG.PTT`, `TX.FRAME`/`TX.SENDING`, explicit flag in `STATION.STATUS`), tolerates the several boolean shapes builds use, and NEVER infers key-down from silence. A socket drop while keyed synthesises key-up or POTACAT's own TX deadlocks. **Why TX detection matters: on a Flex, keying while JS8Call transmits re-points the global `slice set N tx=1` and puts JS8Call's audio out on POTACAT's slice and frequency, with no error anywhere.** Hence `radio-owner.js` gained `js8call` as the first PREEMPTIVE owner — it always wins the acquire and names whom it displaced (`acquireRadio` stands that engine down at the one dispatcher); POTACAT waits it out and never takes it back, because no API command aborts a frame in flight. main.js must NEVER feed JS8Call's dial to `sendCatFrequency()` (it's on its OWN slice — the WSJT-X bridge does this and is right to, because WSJT-X owns the radio) and never write `settings.jtcatLastMode` (Ft8Engine.setMode coerces unknown modes to FT8).
  js8call-threads.js — turns JS8's frame stream into CONVERSATIONS (`Js8Threads`): `threadIdFor` groups by correspondent (a group call like `@ALLCALL` is its own thread), `isHeartbeatText` folds the heartbeat net into a per-thread count instead of a wall of noise, and unread survives the popout closing because state lives in MAIN — an inbox that forgets is just a log. Eviction never discards a thread holding unread mail. Tests: test/js8call-threads-test.js.
  js8call-process.js — finding JS8Call and CONFIGURING it ("open POTACAT, click More > JS8Call, then have JS8Call open and configure to work with POTACAT" — K3SBP 2026-08-06). Pure: `js8BinaryNames`/`js8PathCandidates` (knows the **JS8Call-improved** fork — assuming the stock `js8call.exe` finds nothing on a working install), `js8LaunchArgs` (`--rig-name`), `desiredJs8Settings` (link keys always; CAT/PTT/audio ONLY on explicit `radio`, since moving the operator's radio unasked is POTACAT reconfiguring their station behind their back; `TCPMaxConnections` is RAISED never lowered — JS8Call ships 1, so connecting would evict JS8Spotter), `planJs8IniPatch`, `describeJs8Change`. **This is the one module allowed to write the ini, and only by substituting the value on a named existing line or appending one line to [Configuration] — every other byte passes through** (see js8call-config.js on why a generic INI library destroys the file). main.js enforces the other half: never patch while JS8Call runs (Qt rewrites the file on exit), always write a timestamped `.potacat-<stamp>.bak`, never kill a JS8Call the operator started, and never kill one we started either (it's a window they're looking at, and SIGKILL skips QSettings' shutdown write — which would roll back the patch we just made). Tests: test/js8call-process-test.js.
  js8call-slice.js   — giving JS8Call its OWN receiver on a multi-slice Flex (pure; test/js8call-slice-test.js). **A DAX channel only carries audio if a slice feeds it** — one slice bound to DAX 1 (which POTACAT streams) leaves JS8Call opening a device that works perfectly and delivers silence, with no error on either side. So POTACAT creates a second slice, binds it to a free DAX channel, and JS8Call gets a receiver of its own. `freeDaxChannel` (dax=0 means OFF, never a target), `canCreateSlice` (distinct refusals — "all 4 slices in use" and "POTACAT is not controlling the radio" need opposite actions), `js8SliceFreq` (the JS8 dial for the band already in use). smartsdr.js gained `createSlice`/`removeSlice`/`_sendAwait`. **Flex reality vs the API wiki:** remove is `slice r <n>` NOT `slice remove`; `slice create` returns an EMPTY reply payload on an 8600/v4.2.20 despite the docs promising the index, so the slice is identified by diffing the status stream (poll — the announcement can arrive BEFORE the reply); a new slice comes up ACTIVE and bound mode would adopt it, so `_createBaseline` claims it INSIDE the parser (excluding it after the await is too late — the await resolves on that very status line). Only ever removes a slice POTACAT created, and does so FIRST in gracefulCleanup, before disconnectSmartSdr() makes it impossible.
  js8call TX (main.js `js8KeyForTx`) — on a Flex Direct station JS8Call has `Rig=None`/PTT=VOX because POTACAT owns the CAT link, so **POTACAT must key for it**. Three things, each of which failed silently on its own: (1) `transmit set dax=1` FIRST — TX audio source must be DAX or the radio keys a silent mic, and it must be asserted before (2) because assertFlexTxDaxForTx() needs `txReady`; (2) release POTACAT's own dax_tx stream — `transmit set dax` is per-STATION and the station takes the stream it owns, ours carries nothing while JS8Call has the audio (this alone was a dead carrier: full power, no modulation); (3) `slice set N tx=1` onto JS8Call's slice — it is GLOBAL, so without it JS8Call's audio goes out on the operator's frequency. All three are reversed on key-up, and the TX-slice restore checks the slice still exists ("Slice receiver (0) not in use" if the operator closed it). Prerequisites are SmartSDR + DAX running with a spare slice; the DAX control panel supplies the transmit audio.

  sdr-scope.js       — band scope from a SEPARATE SDR for ANY radio (AB9AI/W9TEF/K6CSG, 2026-10-19): POTACAT is an **rtl_tcp CLIENT** (rtl_tcp for RTL-SDR, rsp_tcp for SDRplay, any rtl_tcp bridge) — never opens a USB device, ships no driver. `parseHeader` (12-byte "RTL0" greeting), `buildCommand` (1 byte + u32 BE; 0x01 freq, 0x02 rate, 0x03 gain mode, 0x04 gain in tenths dB, 0x05 ppm, 0x08 AGC, 0x09 direct sampling), `setupCommands` (re-sent on EVERY greeting — a restarted server comes back at its own defaults), `RtlTcpClient` (backoff, IQ aligned to whole pairs across TCP chunks, named problems `refused`/`unreachable`/`no-header`/`stalled` via `describeSdrError`), `SpectrumBuilder` (Hann + radix-2 FFT 2048, ~12 frames/s whatever the rate — the rest of the IQ is skipped, 3 averaged, DC spike notched, roll-off cropped: `SPANS` 250k→200 kHz / 1.024M→800 kHz / 2.048M→1.6 MHz, peak-hold to 850 levels against an auto-tracking 20th-percentile floor).   jtty-chats.js      — JTTY chats (2026-10-21, mobile handoff jtty-chats-for-desktop.md): a tab per station in the JTCAT window's JTTY pane (FT8 style only), bubbles, composer first, macros behind Quick.
